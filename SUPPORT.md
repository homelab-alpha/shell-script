or discussion — your question may already be answered:

- **[CONTRIBUTING.md](./CONTRIBUTING.md)** — Contribution guidelines and
  development setup.
- **[CHANGELOG.md](./CHANGELOG.md)** — Recent changes and release notes.
- **[Existing Discussions](https://github.com/homelab-alpha/shell-script/discussions)**
  — Browse previous community questions and answers.
- **[Existing Issues](https://github.com/homelab-alpha/shell-script/issues?q=is%3Aissue+sort%3Acreated-desc)**
  — Search for known bugs and tracked requests.

>
> Please do not use GitHub Issues for general questions or support requests.
> Issues are reserved for confirmed bugs and tracked feature requests. Using the

## Reporting Bugs

If you believe you have found a bug, please
[open a Bug Report](https://github.com/homelab-alpha/shell-script/issues/new?template=bug_report.yml)
using the issue template. A good bug report includes:

- A clear and descriptive title.
- Step-by-step reproduction instructions.
- What you expected to happen versus what actually happened.
- Relevant logs, error messages, or screenshots.
- Your environment details (OS, software version, runtime, etc.).

## Reporting Security Vulnerabilities

> [!WARNING]
>
> **Do not** report security vulnerabilities through public GitHub Issues, pull
> requests, or discussions. Public disclosure before a fix is available puts all
> users at risk.

Please follow the process described in our [Security Policy](./SECURITY.md).
Submit a private
[GitHub Security Advisory](https://github.com/homelab-alpha/shell-script/security/advisories/new)
and notify the team by
[opening a Security Issue](https://github.com/homelab-alpha/shell-script/issues/new?template=security_report.yml)
with only the advisory URL — no sensitive details in the public issue.

We aim to respond to vulnerability reports within **72 hours**.

## Response Times

| Request Type              | Target Response                        |
| :------------------------ | :------------------------------------- |
| Security vulnerabilities  | Within **72 hours**                    |
| Bug reports               | Within **5 business days**             |
| Discussions and questions | Best effort by the community           |
| Feature requests          | Reviewed during backlog prioritization |

> [!IMPORTANT]
>
> These are target response times, not guarantees. shell-script is maintained on
> a best-effort basis. If a response is taking longer than expected, a comment
> on your issue or discussion is always welcome.

## Supported Versions
